# Web HIG research brief — 2026-11-13

Sources checked on 13 November 2026. Coverage is 7–13 November 2026. The main action is how coding agents consume Web HIG guidance. Disposition for **v1.18.0**: add consumption metadata for the accessibility, forms, motion, and performance rules; keep animated-image requirements outcome-based and treat `image-animation` as experimental; keep the existing authoring-tool principle and wait for an ATAG draft. No Core Web Vitals definition or threshold changed. No new rule IDs.

## Where Web HIG differs from Modern Web Guidance

MWG is a useful comparison corpus. It is not imported as the requirement. Baseline status is compatibility evidence for the project’s browser matrix. It is not a HIG pass.

| Area | What MWG contributes | What Web HIG keeps | Reason |
| --- | --- | --- | --- |
| Accessibility | Named platform techniques, with Baseline and a fallback, for focus, inert, reduced motion, and form validation | **HIG-A11Y-002** and **HIG-A11Y-003** judge the WCAG outcome and the accessibility tree | A feature name is not conformance. Vendor check rates do not change the mapping. |
| Forms | Guides for accessible validation | **HIG-FRM-001** still requires the label, the timing, the error summary, and preserved input | Error timing and the assistive-technology announcement stay manual. |
| Motion | Reduced-motion techniques | **HIG-A11Y-001** covers every animation technology. `image-animation` is not endorsed. The draft’s example that keeps `img` animations running is not a HIG technique | WCAG 2.2.2 still needs a visible, keyboard-operable control when it applies. One property does not cover video, canvas, or inline SVG. |
| Performance | Scheduling and loading techniques. The 10 November pairing note uses a 50 ms main-thread example with DevTools | **HIG-PERF-001** thresholds are unchanged. Long Animation Frame fields stay diagnostic | A measured LCP, INP, or CLS result is the pass. The 50 ms example is not a HIG threshold. |
| Fallbacks | Widely available features may be used with no extra fallback code. Other features use `@supports`, a small script, or a conditional polyfill | When a HIG rule defines a fallback, test the native branch and the fallback branch in different engines | One engine never exercises both branches. **HIG-SIM-001** may still choose the simpler technique that meets the outcome. |
| Scores | About 50% to about 90% on MWG’s own checks; 43% to 87% on its fallback checks | HIG reports stay multidimensional. A headline rate is not the result | [§8.2](../../HIG.md#82-multidimensional-evaluator-reports-informative) already forbids a single score as the only published metric. |

## Review rationale and compatibility

- **User harm:** Scoring a modern API as success hides a missing pause control, a broken fallback, or an error that is never announced. Treating MWG’s pass rate as a HIG score would launder a vendor harness into a conformance claim. Endorsing `image-animation` now would leave GIF motion running in engines that ignore the property, and would not pause video, canvas, or inline SVG. A new ATAG requirement before a draft exists would invent obligations the W3C has not published.
- **Capability condition:** Consumption metadata applies when an agent or auditor loads an accessibility, forms, motion, or performance rule. The animated-image note applies when a page plays a declarative image, video, canvas, or inline SVG. The authoring-tool note applies to HIG Audit’s interface and generated remediation, not to a new check of scanned sites.
- **Evidence:** Primary sources are linked above. Animated-image fixture execution is pending. No independent accessibility study of MWG is claimed. No cross-engine support claim is made for `image-animation`.
- **Alternatives:** Agents may read MWG as a technique catalog and still have to meet the HIG outcome. Products may use `image-animation` behind feature detection, with a static image, video controls, or a script control beside it. Waiting for the ATAG draft is the alternative to writing an AI-authoring rule this week.
- **Test cases:** For a rule with a fallback, open the native path in an engine that supports it and the fallback path in an engine that does not. For an animated image, operate the pause or stop control from the keyboard, time the motion, and repeat under `prefers-reduced-motion: reduce`. Confirm `image-animation` alone does not clear the row. Read a consumption record and confirm it does not add a pass/fail beyond the existing rule.
- **Exceptions:** No new stable-metric threshold. No WCAG mapping change. No conformance-score change. No new rule ID or severity. No audit credit for the presence of `image-animation`. No normative AI-authoring rule from the 10 November ATAG note. Firefox 160 and the 9 November Media Session draft do not change compatibility expectations.
- **Compatibility:** Backward-compatible packaging for **HIG-A11Y-001** through **HIG-A11Y-008**, **HIG-FRM-001**, **HIG-MOT-001** through **HIG-MOT-005**, **HIG-VT-001**, and **HIG-PERF-001** through **HIG-PERF-004**. Quick remains 98 imperatives. The registry remains 76 stable IDs.

The separate audit site is not implemented or deployed by this repository change. Its checks should follow §8.3. Fixture results must be recorded separately.

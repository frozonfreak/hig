Modern Web HIG

A universal Human Interface Guidelines (HIG) and product-engine contract for modern web applications, commerce sites, and content platforms — designed for humans, linters, CI pipelines, and AI coding agents.

Read HIG-LITE View on GitHub Integration guide

Overview

The Modern Web HIG is not a decorative style guide. It is a web engineering contract that defines design principles, information architecture, state machines, interaction rules, accessibility standards, security requirements, and programmatic enforcement constraints.

Every requirement is written to be testable — by humans during review, by automated linters where possible, and by CI gates for mandatory compliance. Rule IDs (e.g. HIG-A11Y-003) link daily agent context → full specification → future lint rules.

Designers & engineers

Shared UX, accessibility, performance, and security standards across products.

AI coding agents

Deterministic, token-efficient context via HIG-LITE and progressive module loading.

Platform teams

Archetype-scoped rules, CI gates, and a versioned contract you can pin in product repos.

Why it exists

Most HIG documents grow into 15–30k token monoliths. AI agents do not need the entire specification every time they create a button, a checkout form, or a data table. Loading everything wastes context and increases the chance agents invent conflicting rules.

Modern Web HIG solves this with progressive loading: a small default context (HIG-LITE, ~1–2k tokens), archetype-specific module bundles, topic-triggered deep modules, and the full HIG.md only for edge cases.

HIG-LITE and Level 2 modules are extracts of the full specification — not a separate, divergent standard. Every Lite rule maps to a canonical rule ID in HIG.md.

10-Layer Governance Framework

The contract is organized into layers 0–9. Layer 0 defines which rules apply to which page type. Layers 1–9 define the rules themselves.

Layer Focus
0Applicability & Scope — page archetypes and mandatory/optional matrix
1UX Principles — motion, functional micro-animations, spatial ergonomics
2Information Architecture — document fundamentals, navigation, forms, states, i18n
3Visual & Design Tokens — three-tier token system, container queries, data density
4Interaction & State — server-driven rendering, mutations, optimistic UI, offline
5Accessibility — WCAG 2.2 AA, keyboard patterns, focus management, target sizes
6Performance — Core Web Vitals (LCP, INP, CLS), lab vs field metrics, budgets
7AI & Agent Enforcement — rule IDs, severity, YAML guardrails for coding agents
8Quality Assurance — blocking / warning / observation CI/CD gates
9Security & Privacy — CSP, XSS/CSRF, PII, auth UX, audit logging

Page archetypes

Not every rule applies to every page. Resolve archetype before applying rules:

Archetype Examples
Content / MarketingLanding pages, blogs, docs, campaigns
CommerceProduct listings, PDP, cart, checkout
Application / DashboardAdmin panels, authenticated tools, workflows
Auth / AccountSign-in, sign-up, recovery, settings

Accessibility, design tokens, performance, and security are universal — never optional.

Progressive loading

Agents and teams load only what they need. Five levels, from philosophy to full spec:

Level File When to load
0 HIG-CORE.md Session start — vocabulary, archetypes, HIG-SIM-001
1 HIG-LITE.md Default for every UI/CSS/front-end task
1.5 rules/archetypes/ After archetype resolved — preload default module set
2 rules/*.md Topic match (combobox → accessibility, checkout → forms, …)
3 HIG.md Edge cases, spec conflicts, full normative detail 
                    MODERN WEB HIG
                          │
             ┌────────────┼────────────┐
             │            │            │
       HIG-CORE.md   HIG-LITE.md     HIG.md
        Level 0       Level 1       Level 3
                          │
              rules/archetypes/  (Level 1.5)
                          │
              rules/*.md + framework/*.md  (Level 2)

Topic loading is driven by rules/manifest.yaml — a machine-readable index of triggers, rule IDs, and module files.

Archetype packs

Each archetype pack lists default modules to preload and modules to skip. A landing page agent loads ~7 modules; a dashboard agent loads ~15.

Archetype Pack Default modules
Content / Marketing content.md 7 — ux, tokens, responsive, animation, accessibility, performance, security
Commerce commerce.md 13 — adds forms, states, mutations, search, architecture, …
Application application.md 15 — full set including data-density, ai-enforcement
Auth / Account auth.md 12 — security-critical; no decorative motion

Example: accessible combobox

HIG-LITE → archetype pack → rules/accessibility.md → HIG.md §5.3 (if needed)

Integration into your product

Adopt in stages — agent rules first (minutes), lint/CI when ready (hours).

  1. Pin the contract — vendor-copy HIG-LITE.md, HIG.md, VERSION, rules/, and framework/ into e.g. docs/hig/ in your product repo.
  2. Declare archetypes — create docs/hig-scope.md mapping routes to Content / Commerce / Application / Auth (see example).
  3. Wire agents — copy templates from examples/agent-rules/ for Cursor, Claude Code, Copilot, or AGENTS.md.
  4. PR checklist — human review until custom linters exist.
  5. Lint + CI — encode Layer 7 rules as ESLint/Stylelint; run Layer 8 gates (a11y, performance, security).

AI agent workflow

Before writing or changing UI, CSS, or front-end architecture:

  1. Resolve page archetype from product scope doc.
  2. Read HIG-LITE.md (Level 1).
  3. Load archetype pack (Level 1.5) → preload default modules.
  4. Match task keywords against manifest.yaml → load Level 2 modules.
  5. Load framework/*.md when stack-specific (React, Next, Vue, …).
  6. Apply Layer 7 YAML guardrails from agent rule file.
  7. Escalate to HIG.md only for edge cases.
  8. Cite rule IDs when declining conflicting requests.

Do not paste the entire HIG into system prompts. CI is the hard backstop for MUST violations.

Validation & CI

The repository includes contract integrity validation to keep VERSION, manifest, modules, and archetype packs synchronized. 

npm run validate
# or: node scripts/validate-hig.mjs

Checks include:

  • VERSION matches HIG.md, HIG-LITE.md, and manifest.yaml
  • All manifest-referenced files exist
  • All four archetype packs exist
  • Rule ID consistency between INDEX and manifest

GitHub Actions runs validation on every push and pull request to main, and deploys this documentation site.
